TCP vs UDP - Transport Layer Protocols

Protokol transport layer bertanggung jawab untuk mengirim data antar aplikasi. Dua protokol utama adalah TCP (Transmission Control Protocol) dan UDP (User Datagram Protocol).

Perbandingan TCP vs UDP

Fitur TCP UDP
Koneksi Connection-oriented (ada handshake) Connectionless (tanpa handshake)
Keandalan Reliable - menjamin pengiriman Unreliable - tidak ada jaminan
Urutan Menjaga urutan paket Tidak menjaga urutan
Kecepatan Lebih lambat (overhead) Lebih cepat (minimal overhead)
Header Size 20 bytes 8 bytes
Use Case Web, Email, File Transfer Streaming, Gaming, DNS

TCP Three-Way Handshake

TCP menggunakan proses 3 langkah untuk membangun koneksi yang reliable:

Client
Server
Contoh TCP Handshake:
1. SYN: Client mengirim SYN ke Server (Port 80)
2. SYN-ACK: Server membalas dengan SYN-ACK
3. ACK: Client mengirim ACK, koneksi established

Hubungan dengan Port Scanning

Memahami TCP handshake sangat penting untuk port scanning:

  • SYN Scan (Stealth Scan): Mengirim SYN, jika dapat SYN-ACK = port open, jika RST = port closed
  • Connect Scan: Melakukan full TCP handshake
  • UDP Scan: Mengirim UDP packet, jika tidak ada response = port open/filtered
# Contoh Nmap SYN Scan nmap -sS 192.168.1.1 # Contoh Nmap UDP Scan nmap -sU 192.168.1.1 # Contoh Nmap Full Connect Scan nmap -sT 192.168.1.1
Tips Pentesting: SYN scan lebih stealth karena tidak menyelesaikan handshake, sehingga tidak tercatat di log aplikasi.

DNS - Domain Name System

DNS adalah sistem yang menerjemahkan nama domain (seperti google.com) menjadi alamat IP (seperti 142.250.195.78). Memahami DNS sangat penting untuk subdomain enumeration dan reconnaissance.

Jenis-jenis DNS Record

A Record (Address Record)

Memetakan nama domain ke alamat IPv4

Contoh:
example.com -> 93.184.216.34
www.example.com -> 93.184.216.34

CNAME Record (Canonical Name)

Alias dari satu domain ke domain lain

Contoh:
www.example.com -> example.com
blog.example.com -> blogs.wordpress.com

MX Record (Mail Exchange)

Menentukan server email untuk domain

Contoh:
example.com -> mail.example.com (priority: 10)
example.com -> backup-mail.example.com (priority: 20)

TXT Record (Text Record)

Menyimpan informasi teks, sering untuk verifikasi dan SPF/DKIM

Contoh:
v=spf1 include:_spf.google.com ~all
google-site-verification=abc123xyz

NS Record (Name Server)

Menentukan server DNS yang authoritative untuk domain

Contoh:
example.com -> ns1.cloudflare.com
example.com -> ns2.cloudflare.com

Subdomain Enumeration

Subdomain enumeration adalah proses menemukan subdomain dari target domain. Ini penting untuk menemukan attack surface yang tersembunyi.

# Menggunakan dig untuk query DNS dig example.com A dig example.com MX dig example.com TXT dig example.com NS # Menggunakan nslookup nslookup example.com nslookup -type=MX example.com # Subdomain enumeration tools subfinder -d example.com amass enum -d example.com

Teknik Subdomain Enumeration

  1. Brute Force: Mencoba subdomain umum (www, mail, ftp, admin, dev, staging)
  2. DNS Zone Transfer: Mencoba AXFR request (jarang berhasil)
  3. Certificate Transparency: Mencari di crt.sh untuk SSL certificates
  4. Passive Recon: Menggunakan search engine dan OSINT
  5. Permutation: Membuat variasi dari subdomain yang ditemukan
Peringatan: Selalu dapatkan izin sebelum melakukan subdomain enumeration pada domain yang bukan milik Anda!

HTTP/HTTPS - Hypertext Transfer Protocol

HTTP adalah protokol aplikasi untuk transfer data di web. HTTPS adalah versi secure dengan enkripsi TLS/SSL.

HTTP Request Methods

Method Fungsi Contoh Use Case
GET Mengambil data Load halaman, ambil resource
POST Mengirim data untuk diproses Submit form, upload file
PUT Update/mengganti resource Update data user
DELETE Menghapus resource Hapus account, hapus file
PATCH Update parsial resource Update satu field saja
HEAD Sama seperti GET tapi tanpa body Cek metadata, validasi URL
OPTIONS Cek method yang didukung CORS preflight request

HTTP Status Codes

2xx - Success:
200 OK 201 Created 204 No Content
3xx - Redirection:
301 Moved Permanently 302 Found 304 Not Modified
4xx - Client Error:
400 Bad Request 401 Unauthorized 403 Forbidden 404 Not Found
5xx - Server Error:
500 Internal Server Error 502 Bad Gateway 503 Service Unavailable

HTTP Headers

# Request Headers GET /api/users HTTP/1.1 Host: example.com User-Agent: Mozilla/5.0 Accept: application/json Authorization: Bearer token123 Cookie: session_id=abc123; user=john Content-Type: application/json # Response Headers HTTP/1.1 200 OK Content-Type: application/json Set-Cookie: session_id=xyz789; HttpOnly; Secure X-Powered-By: Express Server: nginx/1.18.0

Cookie & Session

Cookie adalah data kecil yang disimpan di browser client. Session adalah data yang disimpan di server.

Cookie Attributes:
- HttpOnly: Tidak bisa diakses via JavaScript (mencegah XSS)
- Secure: Hanya dikirim via HTTPS
- SameSite: Mencegah CSRF (Strict, Lax, None)
- Expires/Max-Age: Waktu kedaluwarsa
# Contoh Set-Cookie Set-Cookie: session_id=abc123; Path=/; HttpOnly; Secure; SameSite=Strict; Max-Age=3600 # Contoh Session ID di URL (tidak recommended) https://example.com/dashboard?session_id=abc123

HTTPS & TLS

HTTPS menggunakan TLS (Transport Layer Security) untuk enkripsi:

  1. TLS Handshake: Client dan server negotiate encryption
  2. Certificate Verification: Client verifikasi SSL certificate server
  3. Key Exchange: Pertukaran symmetric key
  4. Encrypted Communication: Semua data dienkripsi
Security Tips:
- Selalu gunakan HTTPS untuk data sensitif
- Set cookie dengan HttpOnly, Secure, dan SameSite
- Implementasi HSTS (HTTP Strict Transport Security)
- Gunakan strong TLS versions (TLS 1.2+)

Subnetting & Routing

Subnetting adalah proses membagi network besar menjadi network-network kecil. Routing adalah proses menentukan jalur untuk mengirim paket data.

CIDR Notation

CIDR (Classless Inter-Domain Routing) menggunakan notasi /n untuk menunjukkan jumlah bit network:

CIDR Subnet Mask Total IPs Usable IPs Use Case
/32 255.255.255.255 1 1 Single host
/30 255.255.255.252 4 2 Point-to-point link
/28 255.255.255.240 16 14 Small network
/24 255.255.255.0 256 254 Standard LAN
/16 255.255.0.0 65,536 65,534 Large network
/8 255.0.0.0 16,777,216 16,777,214 Very large network

Gateway & Router

Gateway adalah node yang menjadi pintu keluar/masuk dari satu network ke network lain. Biasanya adalah router.

Contoh Konfigurasi:
Network: 192.168.1.0/24
Gateway: 192.168.1.1
DNS: 8.8.8.8, 8.8.4.4
DHCP Range: 192.168.1.100 - 192.168.1.200

NAT (Network Address Translation)

NAT memungkinkan multiple device di private network menggunakan satu public IP untuk akses internet.

Jenis-jenis NAT:

  • Static NAT: One-to-one mapping (private IP to public IP)
  • Dynamic NAT: Many-to-many mapping dari pool public IP
  • PAT (Port Address Translation): Many-to-one mapping menggunakan port berbeda
# Contoh NAT Configuration (Cisco Router) ip nat inside source list 1 interface GigabitEthernet0/0 overload access-list 1 permit 192.168.1.0 0.0.0.255 interface GigabitEthernet0/0 ip nat outside interface GigabitEthernet0/1 ip nat inside

Penting untuk Network Pentesting

  • Network Discovery: Memahami subnet untuk menemukan host
  • Pivoting: Menggunakan compromised host untuk akses network lain
  • Lateral Movement: Bergerak antar subnet dalam network
  • Route Manipulation: Mengubah routing untuk intercept traffic
Pentesting Tip: Gunakan tools seperti ip route, traceroute, dan nmap untuk mapping network topology.

Proxy & VPN

Proxy dan VPN adalah tools untuk anonymization, bypassing restrictions, dan pivoting dalam network pentesting.

Proxy Server

Proxy adalah intermediary server yang menerima request dari client dan meneruskannya ke destination.

Jenis-jenis Proxy:

Jenis Layer Fungsi Use Case
HTTP Proxy Application (L7) Intercept HTTP/HTTPS traffic Web testing, filtering
SOCKS Proxy Session (L5) Forward any TCP/UDP traffic General purpose proxy
Transparent Proxy Network (L3/L4) Intercept tanpa konfigurasi client Content filtering
Reverse Proxy Application (L7) Forward request ke backend servers Load balancing, security
# Menggunakan HTTP Proxy dengan curl curl -x http://proxy.example.com:8080 https://target.com # Menggunakan SOCKS proxy curl --socks5 localhost:1080 https://target.com # Konfigurasi environment variable export http_proxy=http://proxy.example.com:8080 export https_proxy=http://proxy.example.com:8080 # Menggunakan proxychains echo "socks5 127.0.0.1 1080" >> /etc/proxychains.conf proxychains nmap -sT target.com

VPN (Virtual Private Network)

VPN membuat encrypted tunnel antara client dan server, mengenkripsi semua traffic.

VPN Protocols:

  • OpenVPN: Open source, flexible, secure
  • WireGuard: Modern, fast, lightweight
  • IPSec: Network layer, sering untuk site-to-site
  • L2TP/IPSec: Layer 2 tunneling dengan IPSec encryption
  • SSTP: Microsoft proprietary, works through firewalls
VPN Use Cases dalam Pentesting:
- Remote Access: Akses network client dari remote location
- Anonymization: Hide real IP address
- Pivoting: Access internal network through compromised host
- Bypassing Geo-restrictions: Access region-locked resources

Pivoting Techniques

Pivoting menggunakan compromised host sebagai jump point untuk akses network lain:

# SSH Tunneling (Local Port Forwarding) ssh -L 8080:internal-server:80 user@compromised-host # SSH Tunneling (Remote Port Forwarding) ssh -R 2222:localhost:22 user@attacker-machine # SSH Dynamic Port Forwarding (SOCKS Proxy) ssh -D 1080 user@compromised-host # Chisel (HTTP tunneling) # Server side (compromised host): chisel server -p 8080 --reverse # Client side (your machine): chisel client compromised-host:8080 R:1080:socks # Using proxychains with pivoting proxychains nmap -sT 10.0.0.0/24

Proxy vs VPN Comparison

Feature Proxy VPN
Encryption Optional (HTTPS only) Full encryption
Scope Application-specific All traffic
Speed Faster (less overhead) Slower (encryption overhead)
Use Case Web testing, bypassing Full anonymization, secure access
Configuration Per-application System-wide
Legal Notice: Penggunaan proxy dan VPN untuk aktivitas ilegal adalah tindakan kriminal. Selalu gunakan dengan izin dan untuk tujuan yang legal.
Pentesting Best Practices:
- Gunakan VPN untuk melindungi traffic saat pentesting remote
- Implementasi proxy chaining untuk anonymity
- Dokumentasi semua pivot points dan routes
- Test connectivity sebelum engagement
